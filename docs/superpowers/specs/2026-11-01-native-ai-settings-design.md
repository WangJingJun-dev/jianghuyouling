# 原生 AI 设置迁移设计

## 背景与目的

太吾有灵当前的自定义设置窗与游戏原生界面风格割裂，模型、语音、对话、世界书等配置缺少游戏内置感。现有「AI设置」试验实现只迁移了部分助手开关，并以一个合并入口代替助手名字、形象图和人设三个独立参数，不符合完整迁移目标。

本次交付只包含太吾有灵：把八个设置子项完整迁入游戏原生「系统设置 → AI设置」。战斗分类合并已经拆到独立目录 `E:\Work\VibeCoding\TaiWuDev\TaiwuUiOptimizations`，不属于本项目交付。

## 目标

1. 在系统设置中建立名称明确、独立存在的「AI设置」分类，不复用「游戏设置」的标识或名称。
2. 将「模型、体验档位、语音、生图、对话、世界书、过月、助手」八个子项完整迁入原生设置页。
3. 开关、选项、数值、短文本、密钥和长文本均在原生设置页内呈现；不再为迁移功能打开旧 ConfigWindow。
4. 配置保存后继续调用现有存储和运行层刷新机制，支持不重启游戏的热重载。
5. 助手名字、助手形象图、助手人设分别显示为独立参数。助手人设未自定义时显示完整内置默认性格。
6. 世界书在主界面可见但不可编辑，并明确提示需要进入存档。
7. 与独立「太吾界面优化」MOD 同时启用时，双方分类修改保持可组合。

## 非目标

- 本轮不迁移 NPC「人设」。MOD 设置中的 NPC 人设与「杂务 → 人设」的数据关系已确认，但界面去留等待用户实机对比后另行决定。
- 不修改模型协议、密钥加密格式、世界书数据格式、过月行为或主动消息算法。
- 不把 NPC 人设与助手人设合并；两者是不同对象、不同存储和不同作用域。
- 不上传工坊，不修改线上版本。
- 不顺手修复与本次修改无关的既有测试或反编译基线问题。

## 约束

- 唯一太吾有灵开发目录为 `E:\Work\VibeCoding\TaiWuDev\JianghuYouling`，本地运行目录为 `D:\SteamLibrary\steamapps\common\The Scroll Of Taiwu\Mod\JianghuYouling`。
- 新 UI 优化 MOD 的开发目录定为 `E:\Work\VibeCoding\TaiWuDev\TaiwuUiOptimizations`，本地运行目录定为 `D:\SteamLibrary\steamapps\common\The Scroll Of Taiwu\Mod\TaiwuUiOptimizations`。
- 保留现有 DPAPI 密钥保护、持久化读回校验、事务回滚、世界隔离和长文本长度限制。
- 原生设置页缺少现成的单行文本与多行文本控件，需要补充风格一致的自定义 `SettingItemBase` 控件，而不是改用旧窗口。
- 两个 MOD 都会修改 `ViewSystemSetting.Categories`，实现必须幂等、可组合，不能用各自保存的原生初始快照覆盖整个当前数组。

## 方案比较

### 方案一：完整原生内嵌，已选择

八个子项全部进入原生「AI设置」。简单项使用游戏原生控件，文本和长文本使用新补充的原生风格控件。存储、校验和运行逻辑继续复用现有实现。

优点是界面统一、所有迁移功能都有内置感，不再依赖旧设置窗。代价是需要新增文本控件、调整原生布局并覆盖更多交互回归。

### 方案二：原生导航加旧编辑器，不采用

原生页只放简单设置和导航按钮，复杂项仍打开 ConfigWindow。改动较少，但旧界面继续存在，不符合用户明确选择的完整迁移方向。

## 太吾有灵：分类与子项

「AI设置」使用独立的 `ESettingCategory` 扩展值和独立中文标题，不改变「游戏设置」的分类标识、标题或内容。子项顺序如下：

| 子项 | 原生页内容 |
| --- | --- |
| 模型 | 配置档案选择与切换、新档案名称、保存和删除档案、接口地址、密钥、主模型、后台模型、回复上限、上下文窗口、接口测试 |
| 体验档位 | 节省、均衡、最佳三个档位及当前配置摘要；应用档位仍是一次原子批量修改 |
| 语音 | 语音接口、语音密钥、语音资源模型、朗读内容 |
| 生图 | 生图协议、接口、独立密钥、模型、只读输出尺寸、ComfyUI 工作流路径、水印、附加画面风格 |
| 对话 | 难度、回复篇幅、字体大小、太吾口吻、代笔篇幅、代笔自学习、流式输出、显示思量、群聊自动轮数、主动名单人物来信及频率、思考表达提示词 |
| 世界书 | 当前存档世界书的结构化查看与编辑；主界面只读禁用 |
| 过月 | 每月 AI 江湖事件、过月主动行事、自动打开纪事、每月主动人物数量、主动人物名单管理 |
| 助手 | 悬浮助手总开关、主动消息频率、委托发送频率、助手名字、助手形象图、助手人设 |

各子项保留当前生效值、必要说明和失败反馈。密钥输入使用掩码，不写日志，不因迁移改成明文存储。

## 原生控件与编辑行为

「完整迁入」指保留八个子项的现有功能，不用简化版替代复杂编辑器。模型档案管理、接口测试、世界书结构化编辑和主动人物名单管理等能力均需在对应原生子项内完整实现；不能因工作量较大而改成旧窗口入口或削减功能。

### 控件

- 布尔值使用原生 Toggle。
- 枚举和频率使用原生 SwitchButton 或 Dropdown。
- 有界数值使用原生 Slider；需要精确输入的数值使用带校验的文本输入。
- 单行文本和密钥使用新的原生风格单行输入控件。
- 助手人设、世界书、思考表达提示词等多行内容使用新的原生风格多行输入控件，支持滚动、全选、粘贴和既有长度限制。
- 列表和档案操作在对应子项内展开，不弹出旧 ConfigWindow，不新增 Agent 风格窗口。
- 新文本控件必须支持键盘、鼠标和中文 IME 输入，且不得破坏周围原生项的手柄焦点切换。本轮不要求为手柄新增虚拟键盘；没有原生可复用能力时，文本输入本身以键鼠完成。

### 保存时机

- 开关和选项在确认切换后立即保存并刷新运行状态。
- 短文本和数值在结束编辑时校验并保存，不在每次按键时写盘。
- 多行文本提供原生页内保存动作，避免误触和频繁写盘。
- 体验档位、模型档案及现有关联配置继续使用事务，任一必要写入失败时按现有规则回滚。
- 保存失败后重新读取磁盘实际值并显示错误，不把未保存草稿伪装成已生效配置。

### 热重载

迁移不新增第二套配置系统。每个控件继续调用对应 Store 或现有配置服务，并保留运行层通知，包括但不限于：

- 模型配置保存后调用 `LlmService.Reload()`。
- 助手设置保存后调用 `AssistantWidget.NotifySettingsChanged()`；形象变化同时调用 `NotifyFacePathChanged()`。
- NPC 主动消息设置保存后调用 `NpcProactiveChatScheduler.NotifySettingsChanged()`。
- 过月弹窗设置保存后调用 `MonthlyDigestPopup.NotifySettingsChanged()`。
- 对话、字体、流式、思量、代笔等设置保存后同步现有 `TalkOrchestrator`、`ChatWindow` 和字体绑定状态。

## 助手默认人设

助手人设的显示值按以下规则确定：

1. `AssistantPersonaStore` 有自定义内容时，显示自定义内容。
2. 自定义内容为空时，显示 `SpecialPersonaCatalog.AssistantPersona` 的完整内置默认性格，不留空白。
3. 玩家未修改内置默认文本时，不因打开页面或保存其他参数而把它写成自定义人设。
4. 玩家修改默认文本后，保存为自定义人设。
5. 玩家清空并保存后恢复默认性格，编辑区重新显示内置默认文本。

该规则只改变可见性，不改变现有提示词优先级：自定义人设仍优先于内置默认性格。

## 世界书状态

- 主界面和没有有效世界身份时，世界书子项保留可见，所有编辑与保存控件置灰，并显示「请先进入存档，再编辑世界书」。
- 进入存档后，根据当前世界身份加载对应世界书，编辑与保存恢复可用。
- 切换存档、回档或退出世界时，废弃旧加载任务和旧草稿，不把上一世界内容写入新世界。
- 结构化编辑逻辑复用现有存储与校验；原生页内实现编辑呈现，不复用旧 ConfigWindow 外壳。

## 旧界面退场

- 八个子项的原生路径验证通过后，从旧 ConfigWindow 导航中移除对应入口，不保留重复配置入口。
- 原生「系统设置 → AI设置」是八个子项的新唯一入口。聊天中的旧「设置」本轮暂时保留为 NPC「人设」对比入口，待用户给出对比结论后再决定是否改道；不得在本轮提前切断旧 NPC 人设的访问路径。
- 本轮仅因 NPC「人设」待对比而保留其现有实现，不为它制作新的旧式窗口，也不提前决定最终去留。
- 与八个子项相关的旧字段、旧按钮和旧保存分支在确认无调用后删除，避免两套界面继续写同一配置。

## 分类修改的组合规则

该恢复路径有实机证据：用户提供的日志显示，启动时 `ViewSystemSetting.Categories` 为 `SettingCategoryData[]`，语言切换后被替换为 `System.String[]`，随后在 `List<T>` 构造或 `Array.Copy` 中触发 `ArrayTypeMismatchException`。因此类型检测与恢复是必需路径，不是假设性防护。

两个 MOD 均遵守以下规则：

1. 两个 MOD 都在每次 `ViewSystemSetting.Refresh` 前缀中执行各自的分类同步。当前数组仍为 `SettingCategoryData[]` 时，从当前内容执行最小幂等修改，保留其他 MOD 已加入或合并的分类。
2. 检测到共享字段已被替换为不兼容类型时，本 MOD 只从原生五分类基线恢复并应用自己的转换，不使用可能过期的“最后有效完整分类”。另一个 MOD 会在同一次 Refresh 的后续前缀中基于已恢复的有效数组重新应用自己的转换；反向补丁顺序同理。
3. 该协调恢复契约只针对本文的两个 MOD：两者必须保持每次 Refresh 都执行同步。不得依赖加载顺序，也不得通过读取或引用对方程序集实现。
4. 类型有效时不用原生快照覆盖当前数组，不重复添加 AI 分类，不重复追加自动子项；类型失效时也不得把各自记录的其他 MOD 旧状态重新写回。
5. 内容 Holder 和 Toggle 数量按最终分类数组同步，分类语义与索引映射分开处理，禁止把 AI 或自动战斗索引写死。

5. 主界面世界书置灰，进入存档后可编辑，切换世界不串数据。
